01 / Start here · All operating systems

Download & extract everything

You do not need Git, VS Code, or a paid account. You do need Python, the extracted project, and internet for the first dependency installation.

  1. Open the official SharkmanV3 repository

    Use the GitHub project link supplied by the creator. Check that you are on its main file list—not an individual file or a third-party download site. The exact repository address will be provided when the project is published.

  2. Green Code button → Download ZIP

    Above the files, click Code, then Download ZIP. This downloads the currently selected branch. If the creator directs you to a particular release/tag, select that first.

    GitHub’s source ZIP instructions

  3. Extract the ZIP before running anything

    • Windows: right-click the ZIP → Extract All… → Extract.
    • Linux: open your file manager’s archive tool → Extract.
    • macOS: double-click the ZIP in Finder.

    Move the extracted folder to a convenient location such as Documents. Its name might be SharkmanV3-main or include a version number.

  4. Find the project root

    Open folders until you see this layout. This is the project root used in the commands below:

    SharkmanV3-main/
├── GUIDE.html       ← this guide
├── README.md
├── LICENSE
├── WINDOWS/
├── LINUX/
└── MAC/

    Keep the whole folder together. Linux and macOS also use shared code and assets inside WINDOWS/sharkman. Do not keep only your OS folder.

Know what you are installing.

This is a source-code timing-meter assistant, not a full fight or farming bot. It does not navigate or click Continue. It is not affiliated with Roblox. Windows is the primary platform; Linux and macOS are experimental and gameplay-unverified. No configuration guarantees perfect hits.

Next: choose Windows, Linux, or macOS. You only need your own platform’s installation section.

02 / Windows

Windows 10 & 11

Primary platform

  1. Install Python with its desktop components

    Open Python’s official Windows downloads. Choose a stable full Windows installer (64-bit) for a typical Intel/AMD PC—not an embeddable ZIP, source archive, or pre-release.

    The project’s reference Python version is 3.12; the launcher accepts 3.11 or newer. For a new installation, use a currently maintained stable installer. The site’s newest release may differ from the reference version. Do not choose an outdated release just to match its minor version.

    For the traditional installer, enable Add python.exe to PATH. Keep pip, Tcl/Tk and IDLE, and the Python launcher selected, then install. A normal per-user installation is sufficient.

    Installer screens vary. Follow Python’s official Windows installation guide if the site offers the Python Install Manager instead.

  2. Check that Python and Tk work

    Open a new PowerShell or Terminal window after installation. Run these commands one at a time:

    py -3 --version
py -3 -m tkinter

    You should see Python 3.11 or newer, followed by a small Tk test window. Close that test window. If py is unavailable but python --version reports the correct installed Python, use python instead of py -3.

  3. Open a terminal in the extracted project

    In File Explorer, open the folder containing GUIDE.html and the three OS folders. Click its address bar, type powershell, and press Enter. The terminal now starts in the project root.

    Alternatively, right-click an empty area → Open in Terminal. On some Windows versions, hold Shift while right-clicking.

  4. Start SharkmanV3

    py -3 .\WINDOWS\easy_run.py

    The first launch creates a private Python environment and installs dependencies. Let it finish; later launches usually start faster. Keep this terminal open while the app runs.

    After Python file associations are set up, you can also double-click WINDOWS/easy_run.py. If it opens in an editor or closes immediately, use the terminal command so you can read the error.

    Success looks like: the SharkmanV3 Setup window with a v1.0 badge. No game input is sent merely by opening it.

  5. Open Roblox, then calibrate

    Use the installed Roblox client, enter Blox Fruits, and reach the Sharkman timing challenge. Keep the game visible. Run Roblox and SharkmanV3 with the same privilege level—normally neither needs administrator rights.

    Continue to Calibrate the meter.

Environment location: %LOCALAPPDATA%\SharkmanV3\venv-windows. The launcher does not install project packages into global Python.

03 / Linux

Linux with Sober & X11

Experimental · gameplay-unverified
A real X11/Xorg desktop session is required.

Wayland—including running Sober through XWayland—is not supported by this adapter. Run the macro on the Linux host, not inside Sober’s Flatpak, a container, or as root.

  1. Install Python, Tk, and build prerequisites

    Use the block for your distribution. These commands install system prerequisites; the source launcher later installs the app’s Python packages in its own environment.

    Ubuntu / Debian
    sudo apt update
sudo apt install python3 python3-venv python3-pip python3-tk python3-dev gcc libgl1 libglib2.0-0
    Fedora
    sudo dnf install python3 python3-pip python3-devel python3-tkinter gcc mesa-libGL glib2
    Arch Linux
    sudo pacman -Syu python python-pip tk base-devel mesa glib2

    This also performs Arch’s normal system upgrade. Review the package manager’s proposed changes before confirming.

    Check Python and Tk:

    python3 --version
python3 -m tkinter

    Python must be 3.11+ (3.12 is the project reference version). Close the Tk window. If your distribution supplies an older Python, use its supported upgrade process; do not replace system Python manually.

  2. Log into an X11 desktop

    Save your work and log out. At the login screen, choose an available X11 or Xorg desktop session. The menu and available sessions depend on your distribution. After logging in, run:

    echo "$XDG_SESSION_TYPE"

    The result should be x11. If it says wayland, do not continue to live use. If no X11 session is available, this Linux adapter cannot run on your current desktop setup. Do not fake the check by changing environment variables.

  3. Install Sober and open Roblox

    Follow Flathub’s setup instructions for your distribution if Flatpak/Flathub is not configured. Then follow the official Sober installation and requirements.

    flatpak install flathub org.vinegarhq.Sober

    Open Sober from the app menu, finish its setup, and launch Blox Fruits. Sober is experimental and its requirements may change; its own documentation is authoritative for installing Roblox on Linux.

  4. Launch from the project root

    In your file manager, open the extracted folder containing GUIDE.html, then choose Open in Terminal. Run:

    python3 LINUX/easy_run_linux.py

    Allow the initial dependency installation to finish. If you only want to calibrate and test predictions, choose Dry run in Setup. Dry run does not require /dev/uinput access.

  5. Allow virtual input for Live input

    For automatic Space presses, close the macro and run the supplied one-time installer from the project root:

    sudo bash LINUX/install-udev.sh

    This installs a udev access rule and a module-load configuration for uinput. It enables eligible active local users to create virtual input devices. Review the script if you want to inspect the permission change.

    Log out and back in, then check access:

    test -w /dev/uinput && echo "uinput ready" || echo "uinput is not ready"

    Launch the macro again with the earlier python3 command—without sudo. If permission is still unavailable, stay in Dry run and use Troubleshooting.

  6. Bind Sober and calibrate on Linux

    In Setup, use the title Sober or Roblox and click Find and bind current window. Discovery also checks Sober’s X11 window class. Create a Linux-specific profile; Windows/Mac calibration cannot be used to arm this backend.

    Continue to Calibrate the meter.

Environment location: ~/.cache/sharkman-v3/venv-linux, or beneath XDG_CACHE_HOME when set. Missing X Shape support disables only the visible diagnostic overlay; logs remain available.

04 / macOS

macOS 14 or newer

Apple Silicon & Intel · gameplay-unverified

Use the native Roblox client. This is a Python source release—not a signed .app or a .dmg installer. No Mac gameplay tester has completed acceptance yet.

  1. Install Python with Tk

    Open Python’s official macOS downloads and select a currently maintained stable macOS 64-bit universal2 installer. Run the downloaded .pkg and follow its installer.

    SharkmanV3 accepts Python 3.11+; its reference version is 3.12. Prefer native Apple Silicon Python on an Apple Silicon Mac, not a Terminal deliberately running under Rosetta. Do not use a source archive or assume an existing command-line Python includes Tk.

    Official Python-on-macOS instructions

  2. Verify Python and Tk

    Open Terminal and run:

    python3 --version
python3 -m tkinter

    Confirm Python 3.11 or newer and close the Tk test window. If python3 resolves to another installation, use the installed version explicitly, for example python3.12, in the commands below.

  3. Launch the Mac source entrypoint

    In Terminal, type cd (with a space), drag the extracted project folder from Finder into Terminal, and press Return. You should now be in the folder containing GUIDE.html. Run:

    python3 MAC/easy_run_mac.py

    The first run downloads dependencies into a per-user environment. Do not use sudo to run the macro.

    Optional: enable the double-click launcher

    From the same project root, run this once:

    chmod +x "MAC/Start SharkmanV3.command"

    Then double-click Start SharkmanV3.command in the MAC folder. It prefers Python 3.12 if available, otherwise python3. If macOS blocks opening it, review the source and use the system’s explicit Open approval flow. Do not disable Gatekeeper or other security protections.

  4. Grant only the permissions the app needs

    Read the readiness panel in Setup. It separates permission problems by what they block:

    PermissionNeeded for
    Screen RecordingCalibration and runtime capture, including Dry run. No audio is captured.
    AccessibilityPosting Space input in Live input mode.
    Input MonitoringGlobal F2/F4/F8 hotkeys, including the emergency stop.

    Use the readiness panel’s request/settings actions. In System Settings → Privacy & Security, approve the Python/Terminal application that macOS identifies as executing the macro. Screen Recording may be called Screen & System Audio Recording.

    Relaunch if macOS asks, then click Check again. A clicked request button is not proof that permission was granted: the blocker must disappear. You can edit profiles without capture permission; Live input cannot arm without the required input permissions and a working emergency hotkey.

  5. Open Roblox and bind the correct window

    Open the installed Roblox client, enter Blox Fruits, and use Find and bind current window. If more than one client matches, select the intended one. Browsers and Roblox Studio are not eligible.

    Create a Mac-specific profile. Moving the game to another display, changing scaling, resizing, or switching fullscreen can invalidate the binding. Stop and bind again; recalibrate when the geometry changes.

  6. Test locally, then calibrate

    An optional synthetic-window check is available from the project root:

    python3 MAC/easy_run_mac.py --self-test

    It asks for consent before capture and test input, and targets only its own test window. UNAVAILABLE is not a pass. This does not prove Roblox hit accuracy.

    For normal use, relaunch without --self-test and continue to Calibrate the meter.

Mac function keys: you may need Fn/Globe + F2, F4, or F8. See Apple’s function-key guide. Check emergency-stop operation before relying on Live input.
05 / Shared workflow · All platforms

Calibrate the actual meter

Calibration teaches the app where your meter is and which colors to recognize. Reference pictures are instructions only—they do not replace sampling your live screenshot.

  1. Create a named profile and bind the window

    Use a descriptive name, such as Main monitor · windowed. In Setup, find and bind the game. Check its displayed size, DPI/scaling, and display mode. Use separate profiles for different platforms and substantially different setups.

  2. Capture while the timing meter is visible

    Reach a challenge prompt, then choose Open Calibration. The app hides itself to capture the game. If you captured a menu, an animation, or a frame without the meter, use Re-shoot. Keep the game unobstructed.

    If the game cannot be found or the screenshot is black, solve that first. Do not calibrate a desktop or another application.

  3. Complete all four tasks on the left

    TaskWhat to doAvoid
    REGION · Complete timing meterFrame the complete vertical gauge with a small margin. Drag inside the rectangle to move it; use the lower-right grip to resize.Including the character, unrelated scenery, or cutting off the gauge’s top/bottom.
    SAMPLE · Green targetClick a solid green area inside the target band.Yellow transitions, black marker, and antialiased edges.
    SAMPLE · Black markerClick the solid black horizontal moving bar.Shadows, scenery, or the black outline around the track.
    SAMPLE · Track / gradientClick saturated red, orange, or yellow inside the vertical track.Black pixels or background outside the gauge.

    Each click samples a median 5×5 patch. Extra clicks add color variants; they are not required just to fill the list. Remove incorrect variants rather than increasing tolerance until everything matches.

  4. Inspect the magenta preview

    Select a sample group. Magenta shows pixels matched by that group’s saved colors and tolerances. Green should match the green band; marker should match the black bar; track should match the chosen gradient colors.

    Click a variant to adjust its tolerance. Start with the defaults and only change what the preview shows is wrong.

    Zoom screenshot and Zoom reference open larger, read-only viewers. Scroll/trackpad to zoom, drag to pan, and use Fit or 1:1. Close the viewer to sample colors or edit the region in the calibration workspace.

  5. Test detection, then save

    Leave the safe-zone inset at 15% for an initial test. It narrows the accepted target away from each green edge; it does not correct input delay.

    Click Test detection on screenshot. All four tasks being checked is not enough: detection must also identify valid track geometry, green bounds, and the marker. Inspect the detection overlays.

    Then click Save calibration and look for ✓ Saved. An edit or Re-shoot invalidates the previous test, so test and save again after changes.

Ready to continue: 4/4 required tasks, a successful detection test, saved feedback, and a matching bound window.
06 / First run

Choose a mode. Prepare. Start.

Dry run = observe only

The app watches the meter and reports WOULD PRESS. It never presses Space. You still control the game. Use this first to check detection and predictions.

Live input = automatic Space

The app watches the meter and sends Space when its timing conditions pass. This is selected by default on every launch, but the app never starts monitoring automatically.

  1. Choose Dry run for your first check

    In Setup, select Dry run. Leave crop recording off unless you specifically need it. Open Preparation.

  2. Complete the preparation guide

    • The correct client is found and platform permissions are ready.
    • The current window matches the saved calibration.
    • Calibration passed detection and was saved.
    • The game will be visible, unobstructed, and focused during monitoring.
    • You are ready to trigger the timing challenge yourself.
    • You know the selected mode and how to stop it.

    Tick I completed the required preparation checks, then click Finish. If Finish is disabled, read and resolve its blocker; the checkbox does not override invalid calibration or missing permissions.

  3. Focus the game and press F2

    From the Run console, use Start or F2. The default startup delay is one second, giving you time to return focus to the game. Watch the state, prompt count, action count, and logs while testing a few prompts.

    In Dry run, no Space press is expected. The action count describes the engine’s decision, not proof of a successful game hit.

  4. Switch deliberately to Live input

    Stop with F4, return to Setup, select Live input, complete Preparation again, and start while the game is focused. If the game loses focus or its geometry changes, input is blocked. Check status and explicitly restart or pause/resume if necessary.

  5. Stop when finished

    Press F4 before changing windows or settings. Close the app normally. You still handle entering the challenge, Continue buttons, movement, and everything outside the timing meter.

KeyAction
F2Start, pause, or resume monitoring.
F4Emergency stop and release Space.
F8Toggle diagnostics and the overlay when the platform supports it.
07 / Optional tuning

Adjust one setting at a time

Start with defaults. A calibration problem, a changing frame rate, and a late input are different problems; changing every cooldown makes them harder to distinguish.

The gold row: Capture + input latency

This compensates for the delay between the captured image and effective game input. The default is 30 ms. A larger value normally makes the macro act earlier; a smaller value makes it act later. It is not your network ping and should not simply be set to match ping.

  • If the frozen marker repeatedly lands past the target in its direction of travel, try increasing latency by 5 ms.
  • If it repeatedly stops before reaching the target, try decreasing latency by 5 ms.
  • Save, test several comparable prompts, then refine in small steps. Do not judge from a single miss.
  • If misses alternate widely between early and late, record evidence and troubleshoot performance/detection instead of continually increasing latency.

There is no universal 60 ms preset. A value suggested for another tester is not a new default for every Windows 10/11, Linux, or Mac machine.

SettingInitial value / guidance
Scan delay / Scan interval0 ms. This means no added wait, not zero capture time. A higher interval reduces observation frequency; 2 seconds would make timing much worse.
Velocity history80 ms. Leave unchanged for the initial latency test.
Space hold12 ms. This controls key-down duration, not when the press begins.
Other lifecycle/input guardsKeep defaults initially. Do not remove protections against repeated inputs to fix accuracy.
Mac capture ceiling240 Hz requested. This is not guaranteed delivered capture FPS.
Adaptive timingDisabled. The app does not learn or automatically save timing corrections.

Use Save after editing Advanced Cooldowns. Reset restores one field; Reset all restores the timing fields. Timing overrides belong to the selected named profile.

08 / Find the blocker

Troubleshooting

“Python was not found”, the Store opens, or the launcher closes

Use the platform’s terminal launch command above. Check the interpreter version in a newly opened terminal. On Windows, try py -3 --version; if you have several Python installations, choose a supported one explicitly, such as py -3.12. A file opening in an editor is a file-association issue, not a macro failure.

If the command cannot find easy_run.py, you are probably in the wrong folder. Commands in this guide start from the root containing GUIDE.html. Do not run from inside the ZIP.

Missing tkinter / Tk, or dependency installation fails

First run the Tk check for your OS. Windows/macOS full Python installers include the GUI components; on Linux, install the matching Tk system package. Tk cannot be repaired just by pip install tkinter.

Keep internet connected for the first launch. Read the first installation error in the terminal. On Linux, missing compiler/Python headers can prevent evdev from building; check the prerequisite commands. Do not bypass certificate checks, disable security software, or use sudo to run the macro as a workaround.

Roblox/Sober is not found, capture is black, or the wrong image appears

Open the actual game client, restore it if minimized, and bind it again. Keep it visible and unobstructed. Check the title filter. On Linux, verify a real X11 session; on Mac, verify Screen Recording permission. Use Re-shoot after fixing the issue. Never continue calibration using a desktop, another window, or a blank image.

Save calibration or Finish is disabled

Complete the region and all three click-sampled color groups. Pass Test detection after the last edit/Re-shoot, save, then return to Preparation. Tick the required confirmation and resolve the displayed blockers. Merely seeing 4/4 completed tasks does not prove that detection passed.

The app runs but does not press Space

Check the session mode: Dry run intentionally sends nothing. In Live input, confirm the game is focused, calibration matches, the run is not paused, and the meter is detected. Check privileges on Windows, uinput on Linux, or Accessibility/Input Monitoring and the emergency listener on Mac. Read the Run console before changing cooldowns.

Geometry mismatch after moving/resizing the game

Stop. Restore the calibrated window/display setup or bind again and recalibrate. Do not import another platform’s profile to bypass this check. Resolution, DPI/scaling, monitor position, and fullscreen changes can affect the binding.

Linux: no X11 session, no uinput access, or no overlay

If your desktop only supports Wayland, this release’s Linux backend is not compatible with that session. For input permission, run the supplied udev installer once, log out/in, and check /dev/uinput access. Do not make the device world-writable or launch the app as root. An unavailable X Shape extension means no visible F8 overlay; diagnostic logs can still work.

Mac: permissions do not clear or F-keys control media

Approve the actual Python/Terminal entry macOS identifies, relaunch when requested, and click Check again. Replacing Python or rebuilding the environment may change the permission identity. Use Fn/Globe with function keys when needed. If the emergency listener is unavailable, live input stays blocked; do not bypass it.

Small screen: screenshot or reference is hard to inspect

Maximize the calibration window and use Zoom screenshot / Zoom reference. Fit shows the whole image; 1:1 shows original pixels. Pan within the viewer. Return to the normal workspace for color clicks and region edits.

When reporting a problem

Include the app version, OS version, Python version, display resolution/scaling, selected mode, and exact error. For timing issues, mention whether the footage is normal speed and which cooldowns changed. Review any profile, log, or crop before sharing; never send passwords, Roblox cookies, tokens, or an entire personal data folder.

09 / Know where your data goes

Local files & privacy

SharkmanV3 has no telemetry or automatic uploads. Initial dependency downloads need internet; Roblox/Sober have their own network activity and privacy policies.

Calibration and running can capture the game window into memory. Detection uses the calibrated region. On Windows/X11, capture reads visible screen coordinates: another window or notification covering the game can appear in those pixels. Keep the game unobstructed even when it has focus.

Diagnostic logs stay local. Record calibrated meter crops is a separate opt-in setting and saves only the selected crop—not the full window. A badly placed or covered crop may still contain personal information. Leave it off unless needed.

PlatformProfiles, settings & diagnosticsRebuildable Python environment
Windows%LOCALAPPDATA%\SharkmanV3%LOCALAPPDATA%\SharkmanV3\venv-windows
Linux~/.config/sharkman-v3~/.cache/sharkman-v3/venv-linux
macOS~/Library/Application Support/SharkmanV3~/Library/Caches/SharkmanV3/venv-mac-py<version>-<architecture>

Linux follows XDG_CONFIG_HOME / XDG_CACHE_HOME if set. SHARKMAN_DATA_DIR can override profile/diagnostic storage. Exported profiles are saved wherever you choose.

On Windows, paste the data path into File Explorer’s address bar. On Mac, use Finder → Go → Go to Folder. On Linux, enter the path in your file manager (hidden folders may need to be shown).

For contributors/publishers:

Git ignore rules do not protect a manual ZIP of your working directory and do not remove earlier commits. Never publish private editing projects, recordings, profiles, credentials, or a copy of the .git directory. Review staged files and commit-author metadata before uploading.

10 / Maintenance

Update, back up, or remove

Install an update

  1. Press F4, close SharkmanV3, and back up/export any profiles you want to keep.
  2. Download the creator’s new ZIP and extract it to a new folder. Keep all OS folders together. Do not mix individual old and new Python files.
  3. Run the launcher for your OS from the new root. Allow dependency updates to finish.
  4. Check the displayed version and read the release notes. Profiles normally remain in the external data directory, but migrations or changed geometry may require detection testing and calibration again.
  5. Choose Dry run for a short check before returning to Live input.

Back up your setup

Use Setup’s profile Export action, or copy the profiles folder from the data location above while the app is closed. Profiles are platform-specific. Export is a backup convenience, not permission to reuse incompatible geometry on another OS.

Remove the application

Stop and close it, then remove the extracted project folder. Its external profiles, logs, and Python environment remain until you remove them separately. Back up profiles first. On Windows, do not delete the whole SharkmanV3 data folder merely to rebuild venv-windows.

If you installed the Linux uinput integration solely for this macro, the installed files are /etc/udev/rules.d/99-sharkman-uinput.rules and /etc/modules-load.d/sharkman-uinput.conf. Review other uses before removing them through your system’s administrator tools. Mac privacy permissions can be revoked in System Settings when no longer needed.
